# AI-assisted sprite animation workflows

Reviewed November 11, 2026. This comparison covers documented controls and outputs. It does not rank visual quality or latency across providers because we did not run their generators against a shared fixture.

## Documented workflows

| Tool | Motion and character controls | Output and editing |
| --- | --- | --- |
| PixelLab | Animate with Text takes one reference and an action, preserves frame 1, and generates 4–16 frames subject to a pixel budget. The skeleton workflow estimates editable poses from a character and can retarget a template or another animation. | The skeleton workflow can preserve chosen frames, inpaint a region of a generated frame, and save the pose track in an Aseprite document. Its documented canvas sizes include 32×32. PixelLab also documents dedicated skeleton and endpoint interpolation operations. [Text animation](https://www.pixellab.ai/docs/tools/animate-with-text-new), [skeleton animation](https://www.pixellab.ai/docs/tools/animate-with-skeleton), [developer reference](https://api.pixellab.ai/v2/docs). |
| Retro Diffusion | Advanced Animations takes a 32–256 px source sprite and a preset action or custom motion prompt. Its `frames_duration` example selects the frame count. | Advanced Animations returns a GIF. The web tools also export a sprite sheet and let the user set per-frame timing, feet alignment, and pivot during packing. Pose coordinates and region locks are not documented for this generation path. [Advanced Animations](https://retrodiffusion.ai/app/guide/api), [Sprite Sheet Maker](https://retrodiffusion.ai/tools/sprite-sheet-maker). |
| Layer | Its four-pose walk recipe generates each pose from the same approved sprite. The brief specifies the ordered poses, grid, and palette. It advises regenerating a drifting frame from the approved reference. | Each pose takes an image run. Packing uses a file operation and produces a transparent PNG sheet. The guide calls for manual alignment when frame heights drift and nearest-neighbor resampling if the generated pixels are enlarged. [Walk-cycle workflow](https://help.layer.ai/articles/5735031800-make-a-sprite-sheet-and-walk-cycle). |
| Scenario | Its sprite-sheet recipe drives a video generator with a first image and optionally a last image. Its attack example generates the outward and return movements separately. | The recipe asks the user to select important poses from the video, align them, and pack them into a sheet. This gives the artist control of pose selection and timing after generation. [Sprite-sheet workflow](https://help.scenario.com/articles/9088582240-create-spritesheets-with-scenario). |
| Cascadeur | AutoPhysics analyzes existing 3D rig animation and previews a suggested correction using center-of-mass and support points. Priority frames preserve selected poses. | The animator compares a ghost preview and chooses whether to apply the correction to the rig. This pattern applies to reviewing support, weight, and arcs in sprite animation. [AutoPhysics](https://cascadeur.com/help/tools/physics_tools/autophysics). |

## Research on individual in-betweens

Alonso and Patow's October 2026 preprint trains separate RGBA models to generate the preceding, middle, or following frame from two sprite frames. The authors report 8–10 seconds per candidate frame on a Tesla T4. Their evaluation covers 42 held-out triplets and reports failures on extreme squash and stretch, stochastic particles, and occlusion. It includes neither an artist preference study nor an evaluation of whole-loop consistency. This is evidence for testing candidate frames between approved keys. Local generation speed and sequence quality remain open. [Preprint abstract](https://arxiv.org/abs/2610.27253), [failure cases](https://arxiv.org/html/2610.27253v1#S4.E), [reported timings](https://arxiv.org/html/2610.27253v1#S4.F).

## Implications for Aseprite Agent

1. **Give the agent a fixed character and explicit poses.** Reuse the existing Pixel spec and `AI: Reference` layer. The brief should set the target size, facing, palette roles, baseline, pivot, and pose landmarks. Start a walk with the contact and passing poses for both feet. Add up and down poses when the silhouette and weight shift need them. Carry the approved character reference through every generation and use adjacent approved frames when filling a gap. This applies Layer's fixed reference and PixelLab's pose controls to the existing workflows. [Concept](../skills/concept/SKILL.md), [Animate](../skills/animate/SKILL.md).
2. **Revise the smallest part that fails.** Judge a loop at game speed and inspect suspect frames in the filmstrip or onion skin. Lock approved poses and any unaffected parts of a frame. Ask the agent to redraw only the drifting region, such as the near forearm or the planted foot. Recheck adjacent transitions and the loop seam. Preserve user-specified holds and stylized impact poses. Apply accepted pixels and durations to editable Aseprite cels, then run the Check. [Review](../skills/review/SKILL.md), [Check Sprite](../skills/check-sprite/SKILL.md).
3. **Measure craft and elapsed time on the same clips.** Start with the existing 24×32 walk and idle fixture, then add a held impact or fast attack and a prop animation. Compare the current Animate workflow with the same Agent Provider using approved poses and local corrections. Add one sprite-specific generator as an optional third comparison. Ask an animator to score blind playback at 1× and an integer zoom for pose readability, weight, spacing, foot contact, identity, pixel clusters, and loop closure. Record time to first playable draft and time to an accepted result. Break out provider wait, local work, tool calls, cleanup, retries, and manual edits. Keep the exported frames and frame durations so the comparisons can be replayed. [Animation benchmark fixture](../tests/bench/animate.json), [benchmark rubric](../tests/bench/RUBRIC.md).
